# S5 Admin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar autenticação administrativa, dashboard, fila de confirmação e CRUD de presentes.

**Architecture:** Supabase Auth SSR protege a área e cada Server Action. O cliente admin com secret key executa consultas e funções Postgres atômicas; Storage privado serve comprovantes assinados e um bucket público serve imagens de presentes.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript, Supabase Auth/Postgres/Storage, Vitest.

## Global Constraints

- Dinheiro permanece em centavos inteiros.
- `guests` e `claims` nunca são lidos pelo navegador.
- Toda ação administrativa chama `requireAdmin()` antes do cliente com secret key.
- Confirmação vive em uma única função `confirmarPagamento(claimId)`.
- A rejeição cancela imediatamente e devolve cotas atomicamente.
- UI responsiva e coerente com a direção editorial marsala/marfim existente.
